VMaaS Proxy
Created by 

 De Winter Commerina Aletta (BD/ISA-PRC2), last updated by Dietzsch Alexander (BD/ISA-PRC3) on 2026, Aug 14  3 minute read Current Version V 10Page Info
All access to the Internet from a VMaaS virtual machine within the Bosch Private Cloud environment requires a proxy connection, while for all the resources on the Bosch Corporate Network the proxy should not be used.

There are many ways a proxy can be configured depending on the underlying operating system.

All resources from the internet need to be whitelisted if they are not currently available.

The tables below show the recommended settings for proxy configurations within the BHC environment.

IMPORTANT

Automated Proxy Configuration

The proxy settings are configured automatically during provisioning. The settings are not immediately available as they cannot be configured until the VM is started for the 1st time.

Please wait about 10 minutes after the VM is provisioned to start any software installation.

See the links at the bottom of the page to know what settings are configured by default in the VMaaS environment.

If you would like to follow the log files to see if the process has finished you can use the following commands:

Linux:



suddo tail -f /var/log/cloud-init-output.log 




Windows:



Get-Content 'C:\Program Files\Cloudbase Solutions\Cloudbase-Init\log\cloudbase-init.log' -Wait

Proxy Whitelisting
All connections into direction of the Internet are through a proxy server. This proxy server is using a whitelisting for all the endpoints on the Internet that you can access. What is not explicitly whitelisted is forbidden and will be blocked. In case you encounter a missing whitelisting, refer to this guide for instructions on how to request it. VMaaS is currently integrated with the proxy service and provides three REST APIs that can help you to enable your custom domain.

VMaaS Proxy - EMEA Change
Created by 

 De Winter Commerina Aletta (BD/ISA-PRC2), last updated by Dietzsch Alexander (BD/ISA-PRC3) on 2026, Apr 17  3 minute read Current Version V 3Page Info
What is going on?
The existing Internet Web Proxies for the EMEA placement zones (IPZ001, IPZ002, EPZ001 and EPZ002) are subject to replacement. The new proxy endpoint, to be used from now on, is http://rb-proxy-emea.internal.bosch.cloud:8080.

What are the benefits ?
Improve your user experience in streamlining functionality of the BPC proxies and aligning it to that of the Bosch enterprise proxies (e.g. alignment of behavior concerning EntraID MFA)

Where is my attention required ?
In places where you as an application owner are able to select a proxy endpoint, you will have to switch from the current proxy endpoint (10.143.x.y) to the new one: http://rb-proxy-emea.internal.bosch.cloud:8080

If your applications rely on access to resources on the Internet which require a special allowlist, then you need to reach out to the people responsible for those resources in order to have them authorize access from the public IP range of the new proxies (194.39.218.0/23).

Current proxy can reach some endpoints within Bosch Private Cloud whereas new proxy(rb-proxy-emea.internal.bosch.cloud) can not. Using new proxy may require to add endpoints like *.bosch.com, *.bosch.cloud, to NO_PROXY environment variable, in order to bypass proxy access to those domains.

What will not change ?
Apart from the adaptations and improvements described above, many aspects will in fact remain the same as with they are today with the current proxy setup.

These are:

The proxy policy management

The usage of the no_proxy variable in your applications to define that no proxy should be used to access resources in IPZ/EPZ or on the Bosch internal networks

The reachability of the proxies per se (both current and new ones) with respect to Enterprise IT firewall rules which have been put in place for the entire BPC platform

Whitelisted URL currently in use will be automatically replicated to the new proxy, so no changes to whitelist is required.

VMaaS Proxy Configuration on a Linux VM
Created by 

 De Winter Commerina Aletta (BD/ISA-PRC2) on 2026, Feb 06  1 minute read Current Version V 1Page Info
There are two primary location where proxy settings can be configured in Linux.

The file /etc/profile.d directory. Here we create a new file called proxy.sh with the proxy settings for each environment (Internal Placement or External Placement)

The users profile in their home directory. Depending on the shell that the customer uses, the file to be modified would be /home/vmaas/.bash_profile. If the customer changes the shell they will use, then it could be something like /home/vmaas/.csh_profile

NOTE

Please be careful when changing the proxy settings for the "root" user or the system in /etc/profile.d/…​ as changing these settings might affect the connections to the patch management systems.

Location

Setting

Affects

/etc/profile.d/proxy.sh

export HTTP_PROXY=http://<PROXY_HOST>:8080

Systemwide

/etc/profile.d/proxy.sh

export HTTPS_PROXY=http://<PROXY_HOST>:8080

Systemwide

/etc/profile.d/proxy.sh

export NO_PROXY=<NO_PROXY>

Systemwide

HINT: If you have proxy settings or any other setting you need only occasionally, you can create a shell script and use the source command to load these settings into your current session.

Create a New Shell script


vi /home/vmaas/mysettings.sh
...
#!/bin/bash
export mysettings1="New variable setting" 

Load the Settings Into Current Shell


source /home/vmaas/mysettings.sh 

Verify Settings Are Available


printenv | grep "mysettings1"
mysettings1=New variable setting
